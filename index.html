Sovereign Compute Allocation Model

An open, agent-based model comparing ways to allocate scarce public AI compute to Canadian firms: periodic committee review, fixed-term leases, and self-assessed (Harberger) licences. It also includes a quadratic-matching calculator for SME co-funding.

Illustrative model, not a forecast. Results depend on the assumptions in the panel and on the Assumptions & limitations tab. Use it to see which conditions favour each rule, not to predict outcomes.

How the model works

  • Capacity is split into 1 MW blocks held exclusively by one firm at a time, as with dedicated or isolated tenancy for commercial users.
  • Firms alternate between idle spells and runs (training jobs) of random size and length. A run needs all its blocks at once. Each firm has a value per MW-week drawn from a lognormal distribution, and each run varies around it. Total demand is calibrated to the chosen load (demanded MW ÷ capacity).
  • A run that waits longer than the give-up threshold is abandoned. The firm goes abroad or drops the project.
  • Holding an idle block has value: if the next run arrives, the firm avoids waiting for capacity. This option value is the chance of a run next month × the value lost by waiting as long as firms currently wait × the delay-cost factor. It rises when capacity is hard to get, so hoarding reinforces itself.
  • Committee: at each review round, firms with a run, and some recent users "just in case", request their need × a buffer. Reviewers rank requests by value with scoring error and discount speculative requests. Grants last until the next round. Between rounds, unallocated blocks go first-come-first-served, and allocations idle for longer than the reclaim period are taken back.
  • Lease: firms sign fixed-term leases first-come-first-served, but only if their run plus the value of holding the capacity for the rest of the term covers the price. At expiry they renew if holding is still worth the price.
  • Self-assessed licence: at each billing boundary, every holder declares a per-block price equal to the value of finishing its current run plus its option value. The declaration is shaded down by the charge rate relative to market turnover. The holder pays the charge on that declaration. Waiting firms, highest value first, buy the cheapest blocks they need if finishing their run is worth more than the price plus migration downtime. Sellers whose runs are interrupted keep their progress and can buy back in.
  • Migration downtime is charged whenever a block changes hands, under every rule.
  • Results are averaged over many random seeds. All rules face the same demand stream (common random numbers).

What it suggests (default parameters)

  • The biggest losses come from idle capacity that costs nothing to hold: long grants and cheap, long leases. Any rule that makes holding idle capacity costly recovers much of it, including short, market-priced leases and a well-run committee with a short cycle and use-it-or-lose-it reclaim.
  • Self-assessed licences do best on waiting time, abandoned runs and value delivered, because capacity moves to whichever firm values it most at each billing boundary, with no review round.
  • The billing period matters more than the charge rate. Weekly clearing beats monthly. Long migration windows erode the advantage.

Limitations, read before citing

  • Firms do not behave strategically. Declarations follow a fixed rule. The model does not capture overstatement to block rivals, collusion, or gaming of the buyout process. In theory the charge rate disciplines exactly this, so it barely affects allocation here. Here it mainly sets revenue.
  • No shared scheduler or backfill. Real shared HPC systems let other jobs use idle allocations, which would narrow the gap between rules. The model represents dedicated blocks.
  • The status-quo rules are stylised. ISED has not published an allocation mechanism for industry access to SCIP. The committee and lease rules are plausible alternatives, not descriptions of a real program.
  • Values are assumptions. "Value delivered" uses an assumed average value per MW-month of facility power (default C$1.7M, roughly the 2026 one-year rental price of ~570 H100-class GPUs). Changing it scales value and revenue but not utilization or waits. Revenue figures are not comparable across rules: lease revenue is a usage fee, licence revenue is a charge on top of any usage fee.
  • There are no prices for electricity or operations, no demand growth, no firm entry or exit, and no learning. One sandbox pool is modelled in isolation.
